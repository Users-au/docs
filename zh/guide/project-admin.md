# 项目管理

登录设置作用于当前 Users.au 项目。将设置应用到所有用户前，先用普通账户在独立的浏览器会话中测试每条已启用的登录路径。

## 登录与账户访问

| 设置 | 如何配置 |
| --- | --- |
| 登录流程 | 选择同时输入登录标识和密码，或先输入登录标识。检查所选流程可用的免密码和通行密钥选项。 |
| 免密码与通行密钥 | 按项目策略启用邮件验证码和通行密钥。测试验证码送达、通行密钥注册以及更换设备时可用的登录方式。 |
| 社交登录 | 配置所需提供商，并在提供商后台登记 Users.au 项目域名上的回调地址。测试首次登录和关联已有账户。 |
| 多因素验证 | 单独配置首次登录之后的附加验证。发送到同一个邮箱的两个验证码仍依赖同一个邮箱。 |
| 注册与恢复 | 检查哪些人可以注册、需要验证哪些信息，以及如何恢复访问权限。退出登录后逐一测试。 |
| CAPTCHA | 配置验证服务及其保护的操作。正式启用前，在项目域名上测试。 |

## 会话与账户访问

项目会话超时以分钟配置，控制 Users.au 的托管会话。接入应用的会话有自己的设置。OAuth Token 的有效期按应用在 **Integration → OAuth Management** 的 **Token security（令牌安全）** 中设置，见 [Token 有效期](api-reference.md#token-lifetimes)。测试托管会话到期时，仍持有应用会话的用户会看到什么。

在用户管理中可以管理账户并查看登录活动。使用[资料收集](profiles-preferences.md)选择要收集的可选资料字段，以及只能由管理员编辑的字段。

## 品牌外观与返回链接

设置项目品牌外观，并测试托管登录页和账户页。Discovery、Token 交换和 UserInfo 使用同一个项目源地址。更换域名时，检查已登记的全部回调地址和通行密钥注册。

使用[机密客户端 PAR](oauth-oidc.md#pushed-authorization-and-application-context)的应用可从后端提交品牌信息和返回链接。项目的默认登录返回地址应指向应用中**发起**登录的入口，例如接入方式提供的 `/auth/usersau/redirect`。OAuth 回调用于完成登录，需要授权码和对应的 state。
